# Engineering extraction evaluation v1

This is a small **synthetic development corpus**, not a production accuracy benchmark. It contains 15 single-page cases, 50 independently declared gold claims, 13 native-text artifacts and three drawn PNGs (two image-only cases and one hybrid conflict). No customer documents or live model responses are included. The priority families are transformers, LV breakers, cables and utility sources; this is not measured coverage of every registry type.

`v1/corpus.json` declares source hashes/sizes, explicit claim meanings, canonical values/units, mapping statuses, source occurrences and justified associations. Values are authored constants, not results generated by the interpreter/converter. Source spans are checked against the literal UTF-8 text using Unicode codepoints. PNG labels were visually inspected and are re-encoding compatible with the real image processor. The gold is not a claim of independent engineer verification.

`v1/scripted.json` contains separately authored intermediate observation responses and producer resource identities. They exercise the actual M1 validation, M2 interpretation and M3 source verification/conversion. Offline recognition context is a local replay snapshot, not a committed DB success; no provider, broker or database is used. Live execution uses the real committed-context loader instead.

Two recordings are intentional challenge inputs: recognition omits TX-2 in `missed_colon_header`, and `borrowed_tag` proposes a tag outside its equipment expression. Gold still includes the actual source mentions. Rejection/abstention must cost recall, rather than manufacturing a mapped mention or making the denominator smaller. Other cases cover exact Decimal/BIGINT/false, mixed enums, unsupported conversion, overflow, Unicode, isolated/unknown claims, repeated tags/competing values, nonunit qualifiers, no equipment, visual grounding and conflicting modalities.

## Offline command

From the repository environment:

```sh
.venv/bin/python -m powerforge_extraction.eval \
  --corpus evals/extraction/v1/corpus.json \
  --output evals/extraction/private/my-replay.json
```

Create the private output directory first, or omit `--output` to print JSON. `--recordings` selects another recorded-response JSON file; the default is `scripted.json` beside the corpus. Repeat `--case CASE_ID` to score an explicit subset. After package installation, `powerforge-eval-extraction` is the equivalent entrypoint.

The committed [`v1/scripted-report.json`](v1/scripted-report.json) is reproducible from the default command. Source and producer resource identity mismatches, duplicate/unknown case IDs and missing cases fail instead of silently shrinking the dataset. Malformed/overflowed stage responses preserve the case's expected denominators, record a stage failure and publish no partial stage output. An invalid recognition response also prevents replay of dependent attributes. A file claiming live provenance is labeled `UNVERIFIED_RECORDING`; offline replay never claims measured live-model quality.

## Matching and metrics

Matching is one-to-one **within a source case and modality**. It first maximizes matches with correct source location/precision, then performs literal-content fallback using remaining predictions without displacing correct-location matches. The model's local reference IDs, proposed keys, normalized values and statuses do not influence matching. A candidate expression may contain the gold expression. A smaller native fragment may also match when its primary evidence contains the complete gold field. There is no fuzzy semantic/text normalization. Equivalent wording outside this exact source policy can be conservatively missed; inspect per-case issue IDs rather than interpreting the corpus as exhaustive language coverage.

Every rate includes its numerator and denominator; a zero denominator gives `null`, never an invented perfect score. Missing predictions and failed stages remain in reference-based denominators. Counters cover:

- **Equipment precision/recall:** correct type, tag, mapping status and gold grounding / all published equipment mentions or all gold mentions, respectively. Wrong interpretations are not credited merely because their keys are legal.
- **Attribute detection recall:** one-to-one matched source claims / all gold attributes, before mapping correctness.
- **Attribute mapping correctness:** correct status/type/key, equipment association and gold grounding / all gold attributes. Missing claims count against it. UNMAPPED/INVALID targets are explicit outcomes, not forced mappings.
- **Normalized value correctness:** correct mapping, value type and exact Decimal/integer/text/enum/boolean value / all gold MAPPED attributes. **Unit correctness** independently checks their canonical unit, including explicit unitless fields.
- **Raw preservation:** exact original value/unit strings / all gold attributes. **UNMAPPED/INVALID retention** checks the corresponding raw claim/status, location and absence of normalized slots / all gold claims of that status.
- **Grounding location validity:** exact pinned artifact/page, real native snippet and valid codepoint offsets, or honest image-only page markers / all published candidates. **Grounding against gold** additionally checks the reference source occurrence and allowed precision / all published candidates. Native and visual location counters are also separate. Visual location validity is **not independent verification of transcribed text or pixels**.
- **Association correctness:** the correct matched source mention and group, with grounded parent provenance, or a genuinely detached result where required / all gold attributes. **Group separation** checks distinct matched source mentions have distinct nonnull groups; repeated tags do not imply identity.
- **False candidate rate:** unmatched or incorrectly interpreted/grounded candidates / all published candidates. **Unmatched candidate rate** isolates extra claims/duplicates not paired with gold. These rely on this closed corpus's declared annotation scope, not assumptions about arbitrary document completeness.

The report includes per-case counts/issues and rejection categories, corpus/recording hashes, production interpretation/grounding/manifest identities and the evaluator rules hash. It has no arbitrary accuracy pass threshold and performs no model-based judging, repair calls or calculations outside registry normalization. Any future scoring-policy change needs a new evaluator identity and a regenerated, clearly labeled baseline.

## Actual scripted result

The authored recording set contains 49 observations. Replay publishes 48 candidates: 14 equipment mentions and 34 attributes. Equipment precision is **14/14** and recall **14/16**; the two intentional challenges account for the missing mentions. Mapping is **34/34**, typed value/unit correctness **24/24**, UNMAPPED retention **8/8**, INVALID retention **2/2**, and false candidates **0/48**. Grounding location/gold checks are **48/48**, comprising **39 native** and **9 visual page-level** candidates. The borrowed tag is rejected and four uncertain associations are detached.

These numbers measure deterministic replay against scripted inputs. **They do not measure OpenAI extraction precision/recall or production visual recognition quality.** Mutation/negative-control tests verify that omissions, duplicates, wrong values/keys/units, associations, merged groups, bad offsets, foreign artifacts, forged geometry and malformed responses lower scores. No live provider evaluation has been run.

## Separately opt-in live run

The live path requires the worker package, configured PostgreSQL/object storage and explicit external-processing enablement/credentials. It reuses `ExtractionCoordinator` and `execute_unit()`; it never calls the SDK directly or creates canonical equipment. It does not upload, process or classify documents. Prepare the approved fixtures through normal processing first, then bind case IDs to their immutable **Document UUIDs** in a private JSON object. Bindings must be exact/distinct for the selected cases. All selected page-1 artifact roles, SHA-256, sizes and image dimensions must match the corpus before the entire batch commits. Unapproved images are excluded by native-only profiles; image-only cases cannot send an unapproved native representation. Current or mismatched artifacts cause failure, not fallback.

For an initial image smoke test, upload/process the existing `tagless_visual.png` and `breaker_visual.png` through the normal document workflow. These two PNGs preserve their approved analysis-image bytes under the current processor. Native/hybrid cases require matching preprocessed artifact bytes; this tool does not manufacture alternate source representations or weaken the hash check.

After reviewing the fixtures, corpus digest and bindings, an operator may explicitly run:

```sh
.venv/bin/python -m powerforge_extraction.eval \
  --corpus evals/extraction/v1/corpus.json --live \
  --approved-corpus f9f12cb21012d1083500e1ee1b7737184700627661a3ba4155470af741be6ab3 \
  --case tagless_visual --case breaker_visual \
  --bindings evals/extraction/private/bindings.json --max-calls 4 \
  --output evals/extraction/private/live-report.json
```

The digest is the evaluator's canonical validated corpus identity, including source hashes, not `sha256sum` of the JSON file's formatting. CLI approval/selection/budget checks precede worker/SDK imports, and the digest is rechecked before planning. `EXTRACTION_ENABLED` and `EXTRACTION_EXTERNAL_ENABLED` must already be true, with `OPENAI_API_KEY` available only in the worker environment. Use isolated fixture services, not unrelated development data.

Each case pins **two call admissions, one attempt per stage and one concurrent attempt per run**. There are no automatic or manual retries in this evaluation configuration; failures remain measurable. Total possible calls are at most twice the selected case count and must fit `--max-calls`. The complete approved batch commits before provider I/O. Existing workers may claim its durable deliveries, but the same DB budgets/leases/fences remain authoritative. Completed recognition is never resent. `--wait-seconds` bounds the execution polling window; already-started I/O also has the pinned provider timeout. Timeout/interruption cancels only this invocation's unfinished runs, preserving successful outputs/history.

Live reports score committed successful outputs, retain failed cases in gold denominators, and record run/model/profile identities, admission/call counts and published rejection counts. Provider execution success and model discovery quality remain separate. The automated live-runner tests inject providers and report `MOCK_PIPELINE`; they do not spend money or claim live evidence. Private bindings, source files and live reports belong under the gitignored `private/` directory. No real API key, provider response dump or customer document should enter committed reports.
