# Table extraction evaluation v1

This is an offline synthetic development corpus, not a live OpenAI accuracy benchmark. It has **27 cases, 27 gold tables, 146 gold cells and 73 gold claims**: 31 equipment mentions and 42 attributes. There are 23 native-text artifacts, five PNG artifacts and one original positioned PDF, shared by a native-only and a hybrid case. All sources were authored for this repository; no customer or anonymized documents are included. Case-level provenance distinguishes `SYNTHETIC_AUTHORED` from the separately supported `ANONYMIZED_AUTHORIZED` designation. The latter requires an authorization/anonymization note and does not imply consent merely because a file was supplied.

`v1/corpus.json` contains independently authored source layouts, claim meanings, typed values, units, statuses and associations. These are constants based on the sources, not values generated by the normalizer or copied from converter output. Gold cells use row/column coordinates and independently declared spans/header relationships. They contain no model-local table/cell references. Exact source hashes/sizes, native codepoint occurrences and optional original PDF identity are checked before replay. The PNG/PDF layouts have been visually inspected. This is developer annotation, not independent engineer verification.

`v1/scripted.json` contains separately authored intermediate reconstruction and interpretation responses. Replay exercises the actual versioned M1/M2 admission and conversion functions, using an offline validated reconstruction snapshot. It does not claim a committed database prerequisite. Production uses the existing M3 committed-context loader, coordinator and publisher instead. Empty reconstruction skips dependent interpretation, as production does; malformed/overflowed stages retain gold denominators and publish no partial stage output.

## Run offline

From the repository environment:

```sh
.venv/bin/python -m powerforge_extraction.table_eval \
  --corpus evals/tables/v1/corpus.json
```

After installing the extraction package, `powerforge-eval-tables` is the equivalent command. `--recordings PATH` selects another observation recording; the default is `scripted.json` beside the corpus. Repeat `--case CASE_ID` for a subset. `--output PATH` writes JSON. For local experiments:

```sh
mkdir -p evals/tables/private
.venv/bin/python -m powerforge_extraction.table_eval \
  --corpus evals/tables/v1/corpus.json --case pdf_native_unresolved --case pdf_hybrid \
  --output evals/tables/private/pdf-comparison.json
```

The committed `v1/scripted-report.json` is the full reproducible baseline. The report records canonical corpus/recording digests, producer resources and the table evaluator's source identity, including the frozen helpers it reuses. Unknown versions/resources, altered sources, duplicate/unknown selections and missing recorded cases/stage declarations fail closed. A declared null stage payload represents a failed response, not permission to omit that case. There is no arbitrary accuracy pass threshold.

This command imports no SDK, database, worker or broker and offers **no live execution flag**. A file claiming `LIVE_OPENAI` becomes `UNVERIFIED_RECORDING`; replay always sets measured live quality to false. Adding a table live harness is optional future work: it must explicitly approve the corpus, bind exact processing artifacts/pages, budget both stages and use the production coordinator/provider. Injected providers and caller-supplied labels must never designate live provenance. The frozen 6C command and its live controls are unchanged; its scorer is not a table scorer. Do not submit table recordings to the prose evaluator.

## Source matching

Tables first match their independently labeled source occurrence. Native matches require valid artifact/page evidence covering the exact gold anchor span. Visual matches require honest page-level evidence, the visible caption and independent positional cell landmarks. A visual page marker alone cannot select a table. A prediction that fits several indistinguishable source occurrences abstains from matching. Several predictions for one uniquely identified occurrence can earn at most one match; extras remain in precision's denominator.

Cells match by `(row, column)` within a matched table. Their text/state, spans, header roles and relationships are checked separately. Row/column order compares the ordered source-cell signatures, not model-provided row/column IDs. Missing cells/tables stay in gold denominators; extra cells remain explicitly counted.

Claims match one-to-one by source table, primary cell (or specification caption), kind and exact original reading. Neither proposed registry keys, normalized values, mapping statuses, equipment tags/associations nor model-local IDs select a gold claim. There is no fuzzy wording match. This strict policy can conservatively miss alternate excerpts of the same field; inspect case issues before interpreting a score. Claims sharing a value cell, such as `400 AF / 250 AT` or conditional readings, remain distinct by their grounded reading.

Mapping/value credit then requires correct source content, spans/header relationships, admitted orientation/reliability, citations and equipment association. Header citations and their source evidence must exist. Equipment links must point to the matched source-local mention/group; distinct occurrences cannot share a group simply because tags repeat. Exact integer/Decimal, boolean, text and enum values retain their types. Canonical units and raw value/unit preservation are scored separately.

Evidence checks enforce the pinned page/artifact, table/cell ownership, stored locator metadata, actual native snippets/codepoint offsets and honest visual limits. Visual evidence cannot invent offsets, text snippets or geometry, and candidates must retain the explicit visual interpretation marker. Native literal proof and visual relationship reports are separate counters. Agreement with authored visual gold does **not** independently verify a model's transcription or table geometry.

## Metrics and challenge inputs

Every metric exposes numerator, denominator and rate. Empty denominators have rate `null`. Gold denominators persist after missed tables, omissions and failed stages. The counters cover:

- Table precision/recall; row/column counts and placement/order; cell detection/content/spans; complete header relationships; orientation; extra cells.
- Table/cell evidence, native literal reliability, visual-report agreement and admitted structural reliability.
- Equipment precision/recall, attribute detection/mapping, exact typed values/units, raw preservation and source-local association.
- UNMAPPED/INVALID retention, incorrect candidates, incorrect mapped candidates, unmatched claims and duplicate claims.
- Case execution completion, planned-stage completion and claim coverage. Successful empty-table settlement counts as completed stages, while table/claim recall remains independent.

The corpus covers transformer, breaker thermal-magnetic AF/AT, cable length/size/material/BIGINT, utility fault data, attribute-row/tagless specifications, mixed equipment/orientations, repeated tags/headers, blank/missing cells, merged hierarchical headers, multi-tag ambiguity, conditional/conflicting values, multiple tables, unknown types, tag-prefix-only contexts, negative tabular-looking content, and native/image/hybrid evidence.

Four kinds of challenge are intentional:

- `wrong_row_proposal` supplies the wrong equipment association. Gold retains the actual TX-2 owner and mapped value; safe detachment still loses mapping/association credit.
- `mixed_orientation` proposes a label that cannot establish a supported relationship. Its missed uncertain reading remains in gold.
- `failed_reconstruction` and `failed_interpretation` overflow their respective schemas. Earlier successful layouts remain scored; all expected claims remain in denominators.
- `pdf_native_unresolved` and `pdf_hybrid` use the **real document processor** on the same authored PDF. Flattened native tokens cannot prove its positioned grid. Gold retains the visible equipment-row orientation and engineering meanings; native abstention loses recall. The hybrid reading maps with native literal evidence and explicitly visual-reported relationships. One controlled PDF demonstrates this limit; it does not measure its prevalence in operational schedules.

## Scripted result

Replay detects **26/27** tables, with table precision **26/26**, and reconstructs **142/146** gold cells with correct content/spans/headers and evidence. Orientation is **25/27** because the failed reconstruction and unresolved native PDF lose credit. Equipment precision/recall are **28/29** and **28/31**. Attribute detection is **39/42**, mapping **37/42**, and exact typed value/unit correctness **30/34**. UNMAPPED retention is **6/7** and INVALID retention **1/1**. Native literal agreement is **120/124**; visual-report agreement is **21/21**, retaining page-level limits.

There are **68** published claims, **65** fully correct under this policy. Three incorrect outcomes are conservative abstentions relative to source gold: the wrong-row proposal and the two native-PDF claims. **None of the 55 mapped claims is incorrect** in this scripted replay. Duplicates are **0/68**. Execution completes **25/27** cases and **51/54** planned stages. These are deterministic converter measurements on authored observations, **not measured production-model accuracy**. Live quality, real-document coverage and visual transcription quality remain unmeasured.
